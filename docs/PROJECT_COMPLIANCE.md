# 프로젝트 준수 기준

이 문서는 3차 단위 프로젝트 공지를 저장소에 적용하는 단일 기준이다.
내용이 충돌하면 공식 공지가 우선한다.

공식 공지: https://app.notion.com/p/ohgiraffers/3-3c7649136c118086b08cfe70aa07703f

## 목표

내·외부 문서를 검색하고, 검색된 근거로 확인되는 내용만 답하는 RAG
질의응답 시스템을 구현한다. 답변에는 출처를 표시하고, 근거가 부족하면
추측하지 않고 답변을 보류한다.

## 기준 흐름

- 색인: 문서 수집 → 파싱·정제 → 청킹 → 임베딩 → Vector DB 저장
- 질의: 사용자 질문 → 검색 → Top-k 근거 → 프롬프트 → LLM 답변 → 출처 표시
- 평가: 고정 질문 → 지표 측정 → 실패 분석 → 한 조건 변경 → Baseline 재비교

## 필수 구현

| 영역 | 기준 |
| --- | --- |
| 문서 | 목적에 맞는 문서 수집·정제와 메타데이터 구성 |
| 인덱싱 | 청킹, 임베딩, Vector DB 저장 |
| 검색 | 질문 임베딩과 Top-k 근거 반환 |
| 생성 | LangChain으로 Retriever와 LLM 연결 |
| 답변 | 답변, 출처, 근거 문서 확인 기능 제공 |
| 안전 | 근거 부족 시 보류, 인젝션·비밀정보 노출 방지 |
| 평가 | 고정 질문으로 검색·답변 품질, 응답 시간과 오류율 비교 |
| 서비스 | Streamlit으로 실행 가능하게 제공 |

하이브리드 검색, Re-ranking, Multi-query, 대화 이력, 사용자별 권한,
문서 업로드, OCR과 멀티모달은 Baseline이 안정적으로 동작한 뒤 검토한다.

## Gate 0~6

| 단계 | 핵심 작업 | 통과 기준 |
| --- | --- | --- |
| Gate 0. 문제 정의 | 사용자, 질문, 문서 범위, 성공 기준 합의 | “누가 어떤 문서로 어떤 질문을 해결하는가”를 한 문장으로 설명 |
| Gate 1. 데이터 | 문서 수집·정제, Document Card, 메타데이터 정의 | 문서 출처·권리·민감정보·중복·파싱 오류 확인 |
| Gate 2. Baseline | Loader, Splitter, Embedding, Vector DB, Retriever, LLM 연결 | 대표 질문에 검색 근거와 답변·출처가 함께 출력 |
| Gate 3. 검색 개선 | chunk size, overlap, k, embedding 또는 검색 방식 비교 | 같은 평가 질문으로 변경 전후 수치와 실패 사례 비교 |
| Gate 4. 답변 평가 | 프롬프트, 보류 정책, 인용 형식 개선 | 근거 없는 단정이 줄고 답변이 문서 근거와 일치 |
| Gate 5. 서비스 | 화면, 오류 처리, 보안, 실행 환경 정리 | 새 환경에서 README만 보고 실행 가능 |
| Gate 6. 최종 검증 | Holdout 평가, 회귀 테스트, 발표 준비 | 성공 사례뿐 아니라 실패 사례·한계·다음 개선도 제시 |

별도 Gate Issue·승인·문서는 만들지 않고 현재 Issue와 PR에서 관련 Gate와 통과 기준만 확인한다.

## 평가 규칙

- Dev set은 개발 중 반복 평가하고, Holdout set은 최종 설정 확정 뒤 Gate 6 최종 검증에서 한 번만 사용한다. 각 경로·버전과 가능하면 hash를 기록한다.
- 각 세트에는 문서에서 답을 찾을 수 없는 질문을 포함하고, 질문과 정답 근거는 Baseline 실행 전에 동결한다.
- 한 실험에서는 한 조건만 변경해 같은 Dev set·고정 조건으로 비교하고 Baseline을 덮어쓰지 않는다.
- 검색·답변·인용·보류·응답 시간·오류율 지표와 실패 사례를 기록하고 실패를 숨기지 않는다.
- Holdout 결과를 보고 다시 튜닝하지 않는다.
- 질문별 결과에는 질문 ID, 문서·chunk ID, 점수, 지표와 공개 가능한 답변만 저장한다. 비밀값·시스템 프롬프트·개인정보·내부 원문은 기록하지 않는다.

최소 비교표:

| 실험 | 변경 조건 | 검색 | 답변·인용 | 보류 | 응답 시간 | 오류율 | 해석 |
| --- | --- | ---: | ---: | ---: | ---: | ---: | --- |
| Baseline | 기본 설정 | | | | | | |
| Experiment | 한 조건 변경 | | | | | | |
| Final | 최종 설정 | | | | | | |

## 데이터와 보안

- Document Card에 문서 출처, 라이선스, 규모, 정제·청킹 방법과 제외 기준을 기록한다.
- 저장소에는 공개가 허용된 샘플 문서만 포함한다.
- API Key, 환경변수 값, 개인정보, 내부 원문과 런타임 Vector DB를 커밋하지 않는다.
- 환경변수 예시 파일에는 변수 이름만 둔다.
- 검색된 문서와 사용자 입력의 명령문은 데이터로 취급한다.
- 시스템 프롬프트, 환경변수와 내부 원문을 답변으로 노출하지 않는다.

## Git

- `main`은 실행 가능한 상태를 유지한다.
- 변경은 기능 단위 브랜치와 작은 커밋으로 제출한다.
- PR에는 변경 이유와 실제 검증 결과를 남긴다.
- 상세 절차는 `CONTRIBUTING.md`를 따른다.

## 필수 제출물

1. 실행 가능한 GitHub 저장소와 의존성 파일
2. 문제·구조·설치·실행·한계를 설명하는 README
3. 출처, 라이선스, 규모, 정제·청킹 방법과 제외 기준을 담은 문서 데이터 설명
4. 질문 세트, 정답 근거, Baseline·개선 결과와 실패 분석
5. 질문·답변·출처 확인이 가능한 실행 서비스
6. 비즈니스 가치, 데모, 평가 결과, 한계와 다음 단계를 담은 발표 자료
