# 300문장 로컬 모델 비교 계획

## 목적과 범위
기존 실험과 산출물은 보존한다. 새 실험은 이 폴더와 output/llm_comparison_300_20260916에만 기록한다.
정책 상황 100개를 만들고 같은 뜻의 표현 3개씩, 총 300문장을 비교한다.
공개 평가용 정책 8개의 고정 원문만 사용한다. 최신 제도 정확성이나 전체 검색 기능을 검증하는 실험은 아니다.
분류: 일반 25, 정보 부족 20, 경계 조건 20, 질문 대상 구분 15, 근거 없음 10, 잘못된 전제·모순·조작 요구 10.

## 문장 제작
서브에이전트 4명이 서로 다른 정책을 맡는다. 각각 25상황, 상황마다 3문장을 작성한다.
각 상황에는 정책 ID, 사용자가 밝힌 사실, 확인할 사항, 허용되는 답변, 금지할 단정, 원문 발췌가 있어야 한다.
원문에 없는 사실은 질문의 가상 사용자 조건으로만 사용할 수 있다. 정답으로 만들 수 없다.
3개 문장은 사실, 질문 대상, 물어보는 내용을 그대로 유지한다. 인사·감정·말투만 바꾼다.
말투 목록: 정중한 질문, 편한 반말, 짧은 메모, 긴 사연, 급한 말투, 걱정하는 말투, 가벼운 오타, 띄어쓰기 부족, 구어체 존댓말, 항목 나열.
상황 번호를 n(0부터)라 할 때 말투 번호는 n%10, (n+3)%10, (n+6)%10이다. 각 말투는 30문장씩이다.
검토자는 작성자와 분리한다. 발췌의 원문 존재, 답변 기준, 문장 사이 의미 보존, 중복과 부자연스러움을 확인하고 수정한 뒤 동결한다.
이 문장들은 개발용 비교 자료다. 실제 사용자 표본이나 Gate 6 Holdout으로 부르지 않는다.

## 실행 조건
모델: Qwen3.5-9B, A.X-4.0-Light, llama-3.2-Korean-Bllossom-3B. 세 모델 모두 Q4_K_M 양자화 버전이다.
기존 실험에서 확인한 Ollama 0.34.0을 사용한다. Qwen은 CUDA, A.X와 Bllossom은 Vulkan GPU를 사용한다.
별도 로컬 서버 127.0.0.1:11435에서 한 모델씩 실행하며, 사용자의 일반 Ollama 서버는 건드리지 않는다.
공통 설정: 문맥 8192, 최대 출력 1024, temperature 0, top_p 1, top_k 0, repeat_penalty 1, seed 42, num_batch 128. 지원 모델의 thinking은 끈다.
질문 순서는 seed 42로 한 번 섞고 세 모델에 동일하게 적용한다. 모델별 준비 호출은 점수와 시간 집계에서 제외한다.
문장별로 실제 N1 조건 추출과 정책 상세 답변을 각각 실행한다. 두 경로는 독립적이다. N1 결과를 상세 답변에 주입하지 않는다.
정책 상세 답변은 해당 원문과 질문만 제공한다. 검색 결과 차이를 제거한 비교이며 검색·자격 계산 전체 흐름을 재현하지 않는다.
서비스의 기존 프롬프트, 발췌 검사와 같은 모델의 일관성 검사를 그대로 사용한다. 자체 일관성 통과는 정답의 증거로 쓰지 않는다.
기준 날짜는 2026-09-16이다. 원문에 날짜가 지정된 항목은 그 원문 기준으로만 평가한다.
모든 질문과 채점 기준, 서비스 코드, 실행 코드의 해시를 실행 전에 고정한다. 실행 후 결과에 맞추어 바꾸지 않는다.
완료된 문장 결과를 줄마다 저장한다. 중단되면 해시와 모델을 확인한 뒤 완료되지 않은 문장부터 이어간다. 기존 결과 줄은 덮어쓰지 않는다.
연결 오류가 생긴 시도는 별도 파일에 보존하고 중단한다. 명시적으로 재개하면 그 문장부터 다시 실행한다. 답변 형식 실패나 길이 제한은 모델 결과로 남긴다. 동시에 두 실행이 결과를 쓰지 못하도록 잠금을 둔다.
원시 답변, 서비스 최종 답변, 걸린 시간, 오류·길이 제한·형식 실패·차단 사유를 남긴다. 시스템 프롬프트와 환경변수 값은 저장하지 않는다.

## 평가 기준
모델 이름을 가린 검토 자료로 평가한다. 원문과 사용자가 밝힌 조건을 근거로 판정한다. AI 검토이며 사람의 검토를 대신했다고 주장하지 않는다.
- 조건 이해: 명시된 사실과 질문 대상을 정확히 파악했는가. N1이 지원하는 항목만 평가하며 원시 출력과 공통 후처리를 구분한다.
- 답변 도움: 질문의 핵심에 답했는가. 정보가 부족하면 필요한 확인을 하거나 조건을 나눠 설명했는가.
- 근거 충실: 금액·대상·기간·한도를 바꾸거나 원문에 없는 내용을 확정하지 않았는가.
- 표현: 이해하기 쉽고 반복·불필요한 내용이 적은가. 일반 차단 안내문의 유창함은 모델 표현 점수로 넣지 않는다.
- 서비스 차단: 유용한 답변도 차단했는지, 잘못된 답변을 그대로 보여줬는지 따로 기록한다.
- 말투에 따른 안정성: 상황별 세 표현이 모두 올바르게 처리된 비율. 세 번 모두 틀린 경우는 성공으로 보지 않는다.
근거가 없는 질문에서는 확인 불가를 올바르게 알리는 것도 성공이다. 답변을 못했다는 이유만으로 환각이 없으니 우수하다고 평가하지 않는다.
개별 문장 300개 집계와 상황 100개 집계를 함께 제공한다. 말투 변형을 서로 독립적인 300개 상황으로 해석하지 않는다.
모델 크기·양자화 출처·GPU 실행 방식이 다르므로 결과는 이 PC의 배포 설정 비교다. 속도는 참고치로 제공한다.
