# 실행 안정성 보완 기록

기존 질문·채점 기준·manifest·실패 기록을 보존한다. 이 기록은 동결 후 발생한 장치 오류와 그 대응을 설명한다.

## 첫 Qwen 시도
- CUDA 13, 전체 34층 GPU 배치에서 준비 호출과 첫 N1 호출은 성공했다.
- 첫 정책 상세 호출 중 CUDA illegal memory access와 HTTP 500이 발생했다. 서비스 재시도는 응답했지만 연결 오류가 섞인 시도라 별도 실패 파일에 보존하고 중단했다.
- 이때 완료 결과는 0건이다. 파일: runs/qwen_session_001_transport_failure.jsonl.
- 순간 물리 VRAM 측정과 Ollama의 메모리 추정은 다른 값이다. 메모리 압박 가능성을 점검하되 오류의 확정 원인으로 단정하지 않는다.

## 다음 Qwen 시도: GPU 30층 지정
공식 Ollama v0.34.0은 API의 num_gpu로 GPU에 둘 층 수를 지정할 수 있다. 일부 층만 GPU에 두면 이미지 처리 부분도 CPU에 두도록 실행 인자를 추가한다.
따라서 대부분의 텍스트 계산은 GPU를 사용하면서 메모리 부담을 줄이는 방식으로 시도한다. 실제 적용 여부는 새 서버 로그로 확인한다.
모델 파일, 양자화, 질문, 원문, 프롬프트, 문맥 길이 8192, 출력 한도 1024, 샘플링 값, seed, batch는 바꾸지 않는다.
새 실행 진입점 scripts/run_300_qwen_partial_gpu.py에서 num_gpu=30만 추가한다. 이 진입점의 해시와 프로필 해시를 별도로 기록하고 모든 완료 Qwen 행에 연결한다. 원래 동결 실행 코드는 수정하지 않는다.
점수가 좋아지는 설정을 찾기 위한 조정이 아니다. 첫 평가 문장도 완료하지 못한 장치 오류에 대응한 것이다. 속도는 이 배치에서 관측한 참고값이다.
