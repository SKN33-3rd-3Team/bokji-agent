# 대화형 복지 제도 검색 서비스
내가 받을 수 있는 복지 혜택을, 지어낸 답이 아니라 실제 정책 원문 근거로 찾아주는 AI 챗봇

## 팀원 소개

| 이름 | 역할 |
|---|---|
| 이수연 | PM, 데이터수집, 노드총괄 |
| 허유나 | 데이터수집, 노드설계, 모델검수, 발표자료 제작 |
| 김일환 | PM, RAG설계, Streamlit 구현, 파이프라인 고도화 |
| 주상현 | RAG설계, Streamlit 구현, SQL설계 |
| 김길환 | 데이터수집, UI기획, 발표자료 제작 및 발표 |

## 문제 인식
**1. 복지 정책이 너무 많고 흩어져 있다**

보조금24에 등록된 정책만 10,968건. 지원대상, 선정기준, 신청방법이 정책마다 다르고, 어디에 뭐가 있는지 한눈에 파악하기 어렵다.

**2. 내가 해당되는지 스스로 판단하기 어렵다**

소득 기준, 나이, 지역, 중복수급 제한 등 조건이 복잡하게 얽혀 있어서, 정책을 찾아도 "내가 진짜 받을 수 있는지", "얼마를 받는지"는 따로 계산해봐야 안다.

**3. 일반 챗봇에게 물어보기엔 위험하다**

AI 챗봇에게 물어보면 빠르긴 하지만, 근거 없이 그럴듯한 답을 지어내는(환각) 위험이 있다. 복지 지원금처럼 정확성이 중요한 정보에서 이건 치명적이다.

→ 이 프로젝트는 이 세 가지를 해결한다: 실제 정책 데이터를 검색하고(RAG), 모든 답변을 원문과 대조해서 검증한 뒤(환각방지), 근거가 부족하면 지어내지 않고 사용자에게 직접 확인을 요청하는 방식으로 설계했다.

1. **N1~N3**: 사용자 조건(나이/지역/관심사) 파싱 → 지역 하드게이트 확인 → 부족하면 재질문
2. **N4~N6**: 조건에 맞는 정책 검색(RAG) → 자격/금액/중복수급 claim으로 분해 → 원문과 대조 검증
3. **N7~N8**: 근거 충분성 최종 확인 → 부족하면 법령 추가 검색
4. **N9~N12**: 자격 판정 → 지원금액 계산 → 중복수급 판정 → 결과 조합
5. **N13~N14**: 답변 생성 → 근거-인용 최종 검증

### 기술 스택

| 영역 | 사용 기술 |
|---|---|
| 오케스트레이션 | LangGraph |
| 검색(RAG) | Chroma 벡터DB, 임베딩 모델 |
| LLM 서빙 | vLLM + RunPod (skt/A.X-4.0-Light 등) |
| 프론트엔드 | Streamlit |
| 인증 | 자체 구현 (회원가입/로그인, 비밀번호 암호화) |
| 데이터 | 보조금24 API, 국가법령정보센터 API |

### 설계 원칙

생성(Generation)과 검증(Verification)을 분리해서, LLM이 만든 답이 실제 정책 원문과 일치하는지 매 단계 대조한다. 근거가 부족하면 추측하지 않고 사용자에게 직접 확인을 요청한다 (환각방지).
